# Command Argument Type Registry Fix - June 19, 2025

## Initial Problem
- Connection lost error when clients tried to connect to server
- Message: "The server send registeries with unknown keys: ResourceKey[minecraft:command_argument_type / neoessentials:String_to_boolean]"

## First Attempted Fix
- Changed registry key from "string_to_boolean" to "StringToBoolean" to match expected capitalization
- Removed redundant registration via ArgumentTypeInfos.registerByClass()

## Second Problem (Crash)
- The fix caused a startup crash with error: "net.minecraft.ResourceLocationException: Non [a-z0-9/._-] character in path of location: neoessentials:StringToBoolean"
- Minecraft ResourceLocation objects only allow lowercase letters, numbers, and specific symbols

## Final Working Solution
- Restored the command argument type registry name to lowercase "string_to_boolean"
- Kept the removal of redundant ArgumentTypeInfos.registerByClass() usage
- Documented in COMMAND_ARG_FIX.md

## Root Cause Analysis
This was a cascading issue:
1. Initial registration had wrong capitalization compared to what server expected
2. The attempted fix used uppercase letters which ResourceLocation doesn't allow
3. Using a single, consistent lowercase registry name and a single registration method ensures both client/server compatibility and valid ResourceLocation format

## Lessons Learned
- Minecraft registry names must use lowercase [a-z0-9/._-] characters only
- Consistent registration between client and server is critical
- Multiple registration methods for the same resource can cause conflicts
